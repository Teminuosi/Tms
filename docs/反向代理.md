# 给 TMS 面板套反向代理(宝塔 / nginx / Caddy)

> 一句话先说结论:**反代要指向前端口 6366,而且必须转发 WebSocket 升级头。**
> 少了后半句,网页能打开、能登录、看着一切正常 —— **但所有节点永远不上线**。
> 这是这里最难查的一个坑,因为所有表面现象都在说"配好了"。

---

## 一、先搞清两个端口在干什么

装完面板会有两个口(默认值,装的时候被占用会自动往后挑):

| 端口 | 是谁 | 谁在用 |
|---|---|---|
| **6366** | 前端(nginx + 网页) | 浏览器打开面板后台 |
| **6365** | 后端(Spring Boot) | 客户端「指挥舱」、节点上报 |

**关键:6366 那层 nginx 已经把后端全代理好了**(见 `vite-frontend/nginx.conf`):

```nginx
location ^~ /api/v1/     →  backend:6365    # 面板 API
location /flow/upload    →  backend:6365    # 流量上报
location /flow/config    →  backend:6365    # 配置拉取
location /system-info    →  backend:6365    # 节点的 WebSocket(带升级头)
```

所以**反代只要指向 6366 这一个口就够了**,不用把 6365 也暴露出去。

---

## 二、最容易踩的坑:WebSocket 没转发

节点是靠一条 WebSocket 长连接活着的(`/system-info`)。这条连接负责:

- 节点的**在线状态**
- **CPU / 内存 / 开机时间 / 上下行速率**
- **车友的流量统计**

反代如果不转发 `Upgrade` 和 `Connection` 头,这条连接建不起来。而**别的全都正常**:

- 网页打得开 ✅
- 登录进得去 ✅
- 节点列表、协议、车友都在 ✅
- 甚至节点还可能显示「在线」❌ ← 那是数据库里的旧状态,不是真的

**症状**:转发机显示在线但**设备信息全是 `-`**;新加的机器装完 gost 显示 `active`,
却一直「仍在等待上线」;车友流量不再统计。

**判别**:上面三条同时出现,基本就是 WebSocket 没过去。

---

## 三、宝塔怎么配

宝塔的「反向代理」默认模板**不带 WebSocket 支持**,必须手动加。

1. 网站 → 你的域名 → **反向代理** → 添加,目标 URL 填 `http://127.0.0.1:6366`
2. 点该条右边的 **「配置文件」**,在 `location /` 里补上这三行:

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

完整的 location 大致长这样:

```nginx
location / {
    proxy_pass http://127.0.0.1:6366;

    # ↓ 这三行是关键,少了节点永远不上线
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";

    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # 节点是长连接,别让代理把它掐了
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

⚠️ **`proxy_read_timeout` 也别漏**。默认 60 秒,WebSocket 空闲超过就被断开,
表现是节点**反复掉线再上线**,比完全连不上更难查。

## 四、不想折腾就用内置的

面板自带一条命令,自动装 Caddy、自动申请证书、配置全帮你写好:

```bash
tms domain 你的域名.com
```

它会在 80/443 起一个 Caddy 转到前端,证书自动续期。**不需要再装宝塔或手配 nginx。**
关掉:`tms domain off`;看状态:`tms domain`。

前提:域名已经解析到这台机器,且 80/443 没被别的程序占着。

---

## 五、Cloudflare 橙云(小黄云)

**开了橙云,6365 / 6366 都过不去。** CF 只代理固定的几个端口
(80/8080/8880/2052/2082/2086/2095 和 443/2053/2083/2087/2096/8443),
面板用的那两个一个都不在里面。

- 只用 80/443(也就是配好了反代或 `tms domain`)→ **可以开橙云**
- 直接用 `域名:6365` 这种形式 → **必须关掉橙云**(小黄云点成灰色)

另外车友节点用的是 20000-39999 端口段,那些**永远**过不了 CF,
所以订阅里的节点地址不能指向橙云代理的域名。

---

## 六、配完之后还要改两个地方

反代配好 ≠ 就能用了。面板里有两处记着"我的地址",不改的话:

**1. 面板 → 网站配置 → IP**

新装节点的安装命令里带的就是这个值(`./install.sh -a <这里> -s <密钥>`)。
还是旧地址的话,**新装的节点会去连旧地方,装完永远不上线**。

**2. 客户端「指挥舱」里的面板地址**

在客户端重新绑定/更新面板地址即可。

> 换过机器、或者从备份恢复过面板的,这两处尤其容易漏 —— 备份会把旧地址一起带过来。

---

## 七、配完自检

按顺序走一遍,哪步不过就停在哪步查:

1. **浏览器打开域名** → 能看到登录页 → 反代通了
2. **登录进去** → 能看到后台 → `/api/v1/` 代理通了
3. **转发机页面看设备信息** → CPU / 内存 / 开机时间**有数字**
   → **WebSocket 通了**(这步是重点,前两步过了它也可能不过)
4. **客户端绑定面板** → 能拉到转发机列表 → 客户端这条路通了
5. **加一台新转发机** → 装完一两分钟内变「在线」→ 整条链路都通了

第 3 步不过,回头看第二节;第 5 步不过,看第六节的「网站配置 → IP」。

---

## 八、还是不行的话,怎么定位

**看节点那边连没连上:**

```bash
# 在转发机上
systemctl status gost
journalctl -u gost --no-pager -n 50
```

`gost` 显示 `active` 但面板上不上线 = 它活着,只是**连不到面板**(或者连错了地方)。

**看面板后端活没活:**

```bash
# 在面板机上
tms status
docker logs springboot-backend --tail 50
```

**排除反代那一层:** 先用 `http://面板机IP:6366` 直接访问。
直连能用、走域名不能用 → 问题百分百在反代或 CDN 那一层,不用再查面板。
